## Focused patch

Both adapters now use one tested explicit HTTPS site configuration parser. Missing/blank SITE_URL fails closed; malformed URLs, credentials, query/fragment components, wildcard/path origins, empty origin entries, and allowlists excluding the configured site fail validation. ALLOWED_ORIGINS defaults only to the explicitly configured site's origin. Request headers never establish trust. Additional HTTPS origins require explicit configuration; none are automatically permitted.

Intended production values (to be applied only with Bryce's release approval):

- SITE_URL=https://dogehouse.netlify.app/dogehouse-launch.html
- ALLOWED_ORIGINS=https://dogehouse.netlify.app
- Supabase Auth Site URL=https://dogehouse.netlify.app
- Auth redirect allowlist: explicitly include the actual login/recovery redirect URL(s) generated by accounts.js on Netlify. Verify those flows; avoid broad preview wildcards.

The /dogehouse-launch.html URL is included by the current staging script. Confirm it on the deployed artifact before release. Auth configuration is separate from Edge Function secrets and Netlify environment variables; updating only Netlify will not repair these backend functions.
